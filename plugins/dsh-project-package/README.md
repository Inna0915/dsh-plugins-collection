# 项目打包看板

插件版本 0.1.7，兼容 DSH Desktop 0.2.1-rc.3、0.2.1-rc.5、0.2.2-rc.1。入口位于「会话看板」正上方，原生主面板展示项目、构建详情与产物；历史任务收进详情栏的下拉框，不再显示三列任务看板。

0.1.7 修复升级到 0.2.2-rc.1 后被宿主版本检查跳过、入口消失的问题。保留旧版支持，不使用版本豁免。验证范围见仓库 `docs/compatibility-2026-11-05.md`。

首次主动打开才加载面板和打包引擎、读取配置及识别工作区。启动时不扫描项目、不启动 Python/Maven、不访问 Jenkins 或仓库。关闭面板停止监控；正在执行的任务继续，结束后释放空闲引擎。重新打开可查看任务历史。

同一 DSH 窗口内重开面板先恢复上次的项目卡片、所选模块和页签，再恢复实时状态。项目目录列表同时缓存在插件数据目录的 `projects.json`，工作区未变化且已识别 POM 未修改时直接复用；工作区变化、POM 修改或删除会使缓存失效，「重新识别」强制重扫（新增目录也可用此按钮发现）。缓存不保存凭据。

切换项目立即返回项目元数据，Git 在后台刷新，不阻塞卡片切换；连续切换仅保留最新待查询项目，旧查询结果不会覆盖新项目。Git 状态读取从多条命令合并为仓库根查询和一次 porcelain v2 状态查询。

开始打包前快速检查其他 Maven Java 进程；发现已有构建时拒绝本次启动，并提示 PID 与项目目录。普通 Java 服务不受影响，引擎自己的依赖解析任务由引擎取消。开始时不再等待后台监控的网络请求结束，立即记录准备阶段；版本边界使用批量 Git 对象读取，保持原有首父链规则。

版本资源准备在受管理的独立进程中执行，Git/版本服务等待期间也可终止。停止按钮先返回“正在终止”，后台通过 Windows Job Object 回收本次命令及后代；运行时界面状态每 400 毫秒刷新，空闲时降低频率。全部成功后仍自动进入产物页。

## 完整功能

- 自动识别工作区业务项目根目录：以 `*-project-module` / `*-project-starter` 或 `*-p编号-module` / `*-p编号-starter` 配对、starter 为 WAR 为依据，过滤产品库、前端库、框架和示例。支持聚合模块、多个 WAR 模块选择；保留目录输入、系统浏览和最近目录缓存。
- 环境检测；Git 根、分支、upstream、领先/落后、本地改动；刷新远端、干净工作区切换、快进拉取、确认后重置到远端。
- 原有版本服务及最近版本数设置、三份项目版本资源、产品 JAR 说明读取、统一展示模式、Markdown 预览/原文/复制、同包名说明文件。
- 原有 `mvn -B -U clean install -Dmaven.test.skip=true`、实时日志、取消任务；保留 Maven settings 与本地仓库。
- 加壳开关、自动/手动加壳、测试版本前缀、共享目录与服务配置、加壳日志；复制产物文件/说明文件到 Windows 剪贴板、打开产物目录。
- Jenkins / FMS / WMS / Gaia 依赖识别、关联配置、凭据 DPAPI 加密、状态与远端校验、更新提醒、已知晓、实际包内核验。构建成功不代表依赖已经更新。
- 依赖按 Jenkins 任务分组，合并任务名与构建状态；组内保留版本、包内核验详情，并分别统计已包含、有差异、待核验。
- 完整打包流程（包含启用的自动加壳）成功后自动切到「产物」页签；失败或取消保留日志，历史成功记录不会反复抢占当前页签。
- 右上角 Jenkins 实时构建：读取全部任务的最新构建，每 5 秒刷新，运行中置顶，展示最近 12 项、编号、时间、耗时和预计进度。悬浮预览，点击固定，再次点击、点外部或 Esc 关闭。与项目依赖核验独立，本地打包时照常刷新；关闭打包面板即停止轮询。沿用当前 Jenkins 地址和加密凭据，不提交构建。

沿用 `%LOCALAPPDATA%/PackageTool/config.json` 和 `monitor/`。插件任务历史单独保存在 `%LOCALAPPDATA%/PackageTool/dsh-project-package/history.json`。原软件项目位于 `D:/dev/code/tools/project-package`，本插件不修改该项目。

## 开发与安装

运行 `scripts/verify.ps1` 完成有界验证，`scripts/install-local.ps1` 安装。`-Disable` 仅移除本插件 bundle。安装不修改官方文件，不退出 DSH；已装载插件可由宿主 HMR 更新，但启动时因版本不匹配而被跳过的插件可能需要重新启动 DSH。以安装目录 `runtime-status.json` 的版本、当前宿主 PID 和 `active: true` 确认激活。

`engine/core/` 来源于 PackageTool 1.6.1（aa63f5c），保留业务实现。增加了显式产物模块适配；`engine/service.py` 是无界面工作流。`dist/client.js` 只含入口和懒加载壳，`dist/panel.js` 在主动打开后下载。`dist/runtime.js` 由宿主路由首次请求时导入。

开发可使用 Python 3.12+、requests 和 psutil，通过 `DSH_PACKAGE_PYTHON` 指定解释器。发布优先使用 `runtime/PackageEngine.exe`。本机 Git、JDK 和 Maven 仍须可用。

Windows 引擎和命令使用 Job Object 管理所属进程；版本资源准备最长 4 分钟，Maven 最长 60 分钟，加壳本地流程最长 12 分钟。取消远端加壳只能停止本地等待，已提交给加壳服务器的工作可能继续。

工作区扫描有深度、数量和时间上限；复杂目录可输入具体 Maven 根目录。多个产物模块需明确选择。目录未包含有效 POM 时不会作为项目展示。

对于 WMS P329 这类根 POM 未声明模块的项目，兼容根目录下完整的业务模块配对，并依次构建根 POM、module、starter；原有声明完整的 Maven 聚合项目仍只执行一次聚合构建。`wms-project-base` 符合完整业务结构，保留为项目模板。自动列表不按 artifactId 合并不同磁盘路径，以保留不同检出目录。其他 Maven 工程仍可手动输入目录使用。
