# 个人周报 / 月报

建立在 `jira-weekly-report`（周期事件事实）与 `jira-query`（search / history / issue）之上，同样通过 Jira Flow 运行层只读访问 Jira；凭证由运行层管理，不读取、不索要。本 Skill 自带脚本，不依赖另外两个 Skill 所在目录。

## 取数

在本 Skill 目录运行：

```text
node scripts/collect.mjs                                   # 本周：周一 00:00 至下周一 00:00（Asia/Shanghai，结束不含）
node scripts/collect.mjs --period month                    # 本月
node scripts/collect.mjs --period month --date 2026-10-15  # 指定日期所在的周/月
node scripts/collect.mjs --start 2026-10-01T00:00:00+08:00 --end 2026-11-01T00:00:00+08:00
```

可选：`--user <Jira 用户名>`（默认 `JIRA_REPORT_USER`，否则取 `doctor` 返回的当前登录账号）、`--profile work-jira`、`--format json`。脚本并行执行 doctor 与不带正文的 search，再一次批量读取状态历史，周报和月报都在 15 秒左右。

脚本已按下方口径分好组。先看「数据说明」：候选不完整或有历史读取失败时，必须在交付时说明缺口。需要正文判断分类或措辞时，再用 `jira-query` 的 `issue KEY --format markdown` 精读。

## 计数口径

开发后经办人会转给测试（zhanghy 等），所以**不能按当前经办人判断归属**，以状态流转操作者为准：

- **已完成开发任务**：期内由本人转到「Build Done 构建完成」的 Story/Task。
- **已完成 Bug 修复**：期内由本人转到「In Review 审核中」的 Bug。
- **待确认，交付时逐条提示用户**：
  - 上期末修复、本期才验证关闭（如周六晚修复、周一验证）。先确认上期报告是否已写；没写的放本期。
  - 本人直接从「漏斗/打开」关闭、结果为完成，没走测试流转。默认按修复计入，并提示用户。
- **不计入**：解决结果为否决/重复/取消的；他人修复、只经本人审核的；本人报告、他人开发的。
- **前期开发、本期测试关闭**：月报单列为第 3 节；周报默认不写。
- **当前在途**：只用于提示下周/下月计划，不写成已完成事实。

## 项目分类

| P270、PDSTDTTA-11809 托盘满入换库 | P270 楚能中试线 |
| P275 / 半成品 | P275-襄阳半成品 |

| P291 / 291 得壹能源 | P291 得壹能源 |

## 输出格式

每类一行：`项目（N项）：完成…；完成…。`。措辞用「完成 + 动宾短语」，提炼标题要点，去掉托盘号、库位号、复现细节；只有一项且标题过长时可概括。周报不写总数；月报在两节标题后写总数，并加第 3 节。

```text
本周已完成
1. 已完成开发任务：
   - FMS优化（6项）：完成江夏楚能电源柜接口卡顿处理；完成电芯过程数据前端查询；完成工艺调度数据归档重构并支持新归档能力；完成电芯结果数据归档重构并支持新归档能力；完成新增电芯工序过程表；完成调度工序单丢失处理。
   - P269-楚能大储/圆柱（3项）：完成有库存时容器类型规则不允许修改；完成库位实时状态上报；完成新增按排查询库位状态。
   - P270 楚能中试线（1项）：完成托盘入库满入换库后重新分配库位时避免下发历史残留移动任务，确保托盘仅保留一个执行中移动任务。
   - 开利项目（2项）：完成出库分配支持按明细下发任务拣选；完成工作站拣选页面托盘离开按钮防呆，避免重复申请。
   - P329项目现场问题处理
2. 已完成 Bug 修复：
   - FMS优化（1项）：完成入库分配日志记录修复。
```

月报：开头为「本月已完成」，写「1. 已完成开发任务（N项）：」「2. 已完成 Bug 修复（N项）：」，再加「3. 前期开发、本月测试通过关闭（N项）：」。

## 交付

报告放进 text 代码块，方便复制。代码块后简短列出：计数口径一句话、待确认项（逐条带编号）、分类有疑问的条目、不计入的条目及原因、在途事项（供写计划参考）。不自动发布或发送给他人。
